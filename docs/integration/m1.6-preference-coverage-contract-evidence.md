# Milestone 1.6: `preferenceCoverage` Contract-Revision Approval and Notification Record

This artifact records the integration-owner approval and the
parallel-stream notification determination for the shared-contract
revision that introduces the optional `preferenceCoverage` response
field on `feat/m1.6-rank-preferences-group-matching`. It is the
durable evidence required by `AGENTS.md:127` and the integration rules
in `docs/plans/milestone-1-talent-search.md:381-386`, and the gap that
the Codex review on commit `41dc22b` flagged in `P1-002` against
`docs/contracts/search-api.md:319`.

## Why this file exists

Codex review feedback on commit `41dc22b` (P1-002) flagged that the
`## Contract revisions` narrative at `docs/contracts/search-api.md:319`
explains the proposed `preferenceCoverage` field but records no
approver, approval decision/reference, date, or stream notification
recipients/status. That record is captured here with concrete
evidence and referenced from the contract text so the approval and
notification requirement is auditable.

## Exact shared-contract surface changed

The M1.6 branch (`feat/m1.6-rank-preferences-group-matching`) extends
the existing v1 contract with one optional response field. The change
is named with the file and the conceptual purpose so the
integration-owner approval is auditable:

| Surface         | File                                      | Purpose                                                                                                                                                                                                                                                                                                    |
| --------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared types    | `packages/types/src/index.ts`             | Adds the public `preferenceCoverageV1Schema` plus the inferred `PreferenceCoverageV1` type and wires it into `talentSearchResultV1Schema` as an optional field. The schema enforces `matched <= total` and is shared with the browser and the API so neither side holds a parallel handwritten DTO.        |
| Public contract | `docs/contracts/search-api.md`            | Documents the optional response field on `TalentSearchResultV1`, records the omission semantics (field is emitted whenever the buyer supplied at least one canonical preference atom and is omitted only when no preferences were requested), and pins the `## Contract revisions` entry to this evidence. |
| Specification   | `docs/specs/milestone-1-talent-search.md` | Adds the buyer-facing preference-coverage statement to the Implementation Decisions list and names the omission semantics so the service, the runtime schema, the public contract, and the specification describe the same behavior.                                                                       |
